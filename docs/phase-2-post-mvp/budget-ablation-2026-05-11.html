Budget ablation — synthetic-data query

One query, three runs, three slider settings. Same prompt, same day (2026-05-11). How much does the UI budget actually buy?

Headline finding

Run 2 is the peak on every output-quality metric we can compute. Report citations, tier-1 cited sources, peer-reviewed cited sources, and word count all rise Run 1 → Run 2 and fall Run 2 → Run 3. Maxing the sliders produced a shorter report with fewer tier-1 citations than the middle setting — for ~2× the tokens of baseline.

What the three sliders actually control

These are the three knobs exposed in the UI settings panel. They compose multiplicatively as a theoretical ceiling on total search calls — but the actual consumption is set by the prompts, not the caps.

analyst_budget

Researcher (Opus) enforces
Gates investigate_question. Max sub-questions the researcher can dispatch. All three modes (explore, verify, adversarial) draw from the same pool.
Run 1 cap8 → used 6 (75%)
Run 2 cap12 → used 7 (58%)
Run 3 cap16 → used 7 (44%)

scout_budget_per_analyst

Analyst (Sonnet/GPT-5) enforces

Run 1 cap4 × 6 analysts = 24 → used 13
Run 2 cap6 × 7 = 42 → used 31
Run 3 cap8 × 7 = 56 → used 29

Scout (Haiku) enforces

Run 1 cap=80 exhaustions (non-binding)
Run 2 cap=1619 exhaustions (binding!)
Run 3 cap=200 exhaustions (non-binding)

Why raising budgets doesn't scale — two prompt ceilings

Two literal lines in the agent prompts explicitly tell the agents to stop spending budget before they hit the cap. These are the real throughput limits.

Researcher ceiling
"Never call `investigate_question` just because budget is left over.
Stop when the report won't improve."
Effect: researcher tops out at 6–7 sub-questions on a 4-axis prompt. analyst_budget past ~8 is dead weight.
Analyst ceiling
"Don't over-investigate. 4–8 deep-read sources beats 20 half-skimmed ones."
Effect: ANALYZED/analyst is 5.5 → 6.0 → 6.1 across all three runs. Each analyst deep-reads ~6 sources regardless of how many are in the graph.

Because ANALYZED = analyst_count × ~6, and analyst_count tops out at 6–7, the evidence base of the final report is hard-capped at roughly 42–56 deep-read sources. All three runs sit in this band (33 / 42 / 43) regardless of total budget. Raising scout_* sliders adds SCOUTED notes but none of them get analyzed — they become untiered cruft.

The scout_search_budget slider is the one that has empirical grip. At the default of 16, scouts in Run 2 got cut off in the middle of their search arc.

Run 2 compensated by dispatching more total scouts (31) — which is why Run 2's report is still the highest-quality — but the cap was costing per-scout completeness.

The wider scout funnel dilutes the quality mix instead of improving it.

Orthogonal finding: Run 2 bypassed cross-family routing

Run 2 dispatched all 7 investigations in explore mode — zero verify, zero adversarial — even though two of its sub-questions were literally titled [adversarial] Steelman the position that.... ADR-0008 says the model challenging a claim should come from a different family than the model that produced it, and verify/adversarial modes route to the GPT family for exactly that reason. Run 2 bypassed this entirely — the steelman questions ran on the same family as the original explores.

Notable: Run 2 still produced the highest-quality report on every output-quality metric, despite skipping the cross-family discipline. This argues that decomposition shape + per-analyst source depth dominate cross-family judgment for report quality on this query. The routing-discipline bug is orthogonal to the budget story — worth fixing, but not what's moving the numbers.

What each report hit — and what it missed

Each run investigated a different 5th/6th/7th sub-question set. None of the three reports is a superset of another — they're qualitatively different, not progressively better.

Run 1 · 8/4/8

Tight and disciplined; narrowest scope
Picked up
  • Explicit verification dispatch for the preference-leakage claim — the one report that treats single-source numbers with meta-methodological rigor.
  • Knowledge-collapse three-stage framework — including Stage B "valley of dangerous competence" (fluent + format-correct + factually wrong).
  • Position-bias disagreement is surfaced explicitly (two studies disagree).
  • Verbosity-bias inversion (modern judges prefer concise).
  • A tight "five non-negotiables" practitioner checklist.
  • Proper cross-family routing: 1 verify + 1 adversarial routed to GPT-5.4.
Missed
  • Domain-specific risks (medical, legal, finance).
  • Medical data poisoning attack (0.001% tokens → harm).
  • PII leakage / training-data extraction.
  • Regulatory surface (EU AI Act, FDA).
  • Fairness-aware synthetic generators as mitigation.
  • Privacy-specific defenses and MIA results.

Run 2 · 12/6/16

Broadest; highest citation density
Picked up
  • Nature Medicine 2024 medical poisoning attack — 0.001% of training tokens → clinically harmful outputs; benchmarks fail to detect; only knowledge-graph filtering works.
  • Neural phishing / PII extraction across Pythia, GPT-2, Falcon, LLaMA-2.
  • DPO-as-bias-amplifier at Qwen3-32B / Llama-3.3-70B — "the only training regime where a model can become meaningfully more biased while still appearing functional."
  • Fairness-aware generators: MCRAGE, FairFinGAN, SMA — when synthetic data reduces bias vs. biased real baseline.
  • 16-row cross-cutting mitigations matrix with validated/partial/refuted tagging.
  • Broadest regulatory footprint (EU AI Act, GDPR, FDA silence).
Missed
  • No dedicated preference-leakage verification step.
  • Position-bias contradiction not engaged.
  • Does not quantify the per-model-size safe fine-tuning ratio (410M vs. 12B).
  • Skipped all verify / adversarial modes — the steelmans ran on the same model family as the explores, bypassing ADR-0008 cross-family discipline.

Run 3 · 16/8/20

Dense privacy + governance; regressions elsewhere
Picked up
  • JP Morgan Six Levels of Privacy — the clearest operational framework in any of the three reports.
  • DCR Delusion — standard Distance-to-Closest-Record privacy proxies have no correlation with actual MIA vulnerability.
  • Quantified MIA numbers: 97.8% AUC full FT, >80% LoRA without DP; 3.9% → 73.1% PII extraction under adversarial attack.
  • UniLeak layer-level attacks; Google DP-SGD + LoRA production case.
  • Equilibrium-bias dynamics — bias converges to a generator-inherent fixed point rather than monotonically amplifying.
  • Precise mixing-ratio scaling (410M safe to 15%; 12B safe to 27%) with task sensitivity ordering.
  • EU AI Act compliance specifics: August 2, 2025 / 2026 / 2027 dates; €10M or 2% global turnover penalties.
Missed (regressions)
  • Medical data poisoning — the single most load-bearing safety finding from Run 2 — is gone.
  • DPO-as-bias-amplifier is gone.
  • MCRAGE / FairFinGAN / SMA fairness generators are gone.
  • No explicit verification dispatch for any contested claim.
  • Fewer peer-reviewed sources cited (4) than Run 2 (13).
  • Shortest report overall despite highest cost.

Interpretation & implications

The behavioral model

  1. analyst_budget is non-binding on a 4-axis prompt. The researcher decomposes into 6–7 sub-questions and stops. Raising the cap from 8 → 12 → 16 adds 0–1 actual investigations.
  2. scout_budget_per_analyst is non-binding once the corpus is full. Analysts stop dispatching scouts when list_source_notes looks "enough." Larger per-scout yields actively reduce scout dispatches.
  3. scout_search_budget is the one slider with real empirical grip. At 8 it's over-provisioned. At 16 it's under-provisioned (19 exhaustions in Run 2). At 20 it's sufficient. This slider controls how complete an individual scout's search arc can be.
  4. The ANALYZED stage is the bottleneck on report evidence, bounded by analysts × 4–8 deep reads ≈ 42–56 under the current prompts. Extra scout output never becomes evidence.
  5. Decomposition shape dominates everything: the 5th/6th/7th sub-question choice matters more than any slider. Planner's decomposition is high-variance across reruns, and that variance drowns out the budget effect.

What this means for the code

  • Don't raise scout_search_budget past 20 without also raising the analyst's "4–8 deep-reads" ceiling — otherwise extra scouting just inflates SCOUTED counts without improving the evidence base.
  • analyst_budget past ~8 is dead weight on a 4-axis prompt. The UI should either hide the top of that slider or couple it to a planner-depth knob that actually changes decomposition.
  • Run 2's all-explore behavior is an independent bug. When the researcher labels a question [adversarial] or [verify] in its title, it should also pass the matching mode to investigate_question.
  • Decomposition stability is a better thing to measure and optimize than budget utilization. A planner that reliably emits a verify question for single-source claims would make Run 1's methodological discipline the default.

What changed as a result

Default slider values in run_config.py updated from 8 / 4 / 8 to 12 / 6 / 16 (Run 2's settings). The UI reads these via GET /api/config/defaults, so the slider preselect will now land on the best-performing configuration observed. Note: analyst_budget=12 and scout_budget_per_analyst=6 are over-specified for what the prompts actually consume — only scout_search_budget=16 has a real effect, and even that was empirically under-provisioned (19 exhaustions). Raising only the search budget to 20 would likely match Run 2's output at ~70% of Run 3's cost.

Caveats. n=1 per configuration. Analyst-model routing bounced across runs (GPT-5.4 × 2 / Sonnet only / GPT-5.5 × 1) in ways not attributable to budget. Same seed/query throughout — can't distinguish "budget helped" from "this query's decomposition converged at Run 2." All three reports are plausible; differences are in scope, methodological discipline, and citation density, not correctness.
